# גלריית שמחת התורה

אתר גלריה פרטי המבוסס על GitHub Pages ו־Cloudflare בלבד. Firebase אינו נדרש להפעלת האתר.

## רכיבי המערכת

- `index.html` — מבנה ה־HTML בלבד, וקישורים לגיליון הסגנון ולמודולים.
- `styles.css` — כל העיצוב של האתר.
- `app.js` — נקודת הכניסה: אתחול, מצב משותף, עזרים וחיבור בין המודולים.
- `gallery.js` — הצגת הגלריה, מדיה, ניווט ותיקיות.
- `drive-sync.js` — חיבור וסנכרון Google Drive, סריקה רקורסיבית, מחיקות ותיקיות ריקות.
- `admin.js` — ממשק הניהול, משתמשים, דרגות, הרשאות והודעות.
- `face-search.js` — חיפוש הפנים: הפקת טביעה מתמונת החיפוש והשוואה בענן.
- `face-index.js` — הכנת חיפוש הפנים: אינדוקס חד־פעמי של הגלריה ואינדוקס אוטומטי לתמונות חדשות.
- `cloudflare-client.js` — התחברות Google ישירה ושכבת הנתונים של D1.
- `cloudflare-worker.js` — API מאובטח, אימות Google, D1, R2, Drive, דוא״ל, חיפוש AI וחיפוש פנים.
- `cloudflare-d1-schema.sql` — מבנה מסד הנתונים.
- `sw.js` ו־`manifest.webmanifest` — התקנה כאפליקציה ומטמון מגורסן.

מנוע זיהוי הפנים אינו נטען בפתיחת האתר; הספרייה והמודלים יורדים רק
בפתיחת כלי חיפוש הפנים, פעם אחת לכל כניסה.

## חיפוש פנים בענן

כל תמונה מעובדת פעם אחת בלבד, וטביעות הפנים שלה (וקטור של 128 מספרים לכל
פרצוף) נשמרות ב־D1. חיפוש רגיל אינו מוריד ואינו סורק מחדש את תמונות הגלריה:
הדפדפן מפיק טביעה מתמונת החיפוש בלבד, שולח אותה ל־Worker, וה־Worker מחזיר רק
מזהי תמונות עם מרחק ואחוז התאמה. תמונת החיפוש עצמה אינה נשמרת, ו־descriptors
אינם מוחזרים ללקוח ואינם נכתבים ליומן.

ערכי הסף נשמרו כפי שהיו: התאמה רגילה `0.62`, התאמה חזקה `0.48`.

### הכנה חד־פעמית של התמונות הקיימות

1. היכנס כמנהל, פתח את לוח הניהול ובחר **הכן חיפוש פנים בענן**.
2. לחץ **התחל או המשך אינדוקס**. התמונות מעובדות בקבוצות קטנות, והמסך מציג
   כמה הושלמו, כמה נותרו וכמה נכשלו.
3. אפשר לעצור בכל רגע. ההמשך — גם אחרי רענון או סגירת הדפדפן — מתחיל מהמקום
   שנעצר, משום שמצב האינדוקס נשמר ב־D1 ולא בדפדפן.
4. תמונה שכבר עובדה באותה גרסת מודל נידלגת, ותמונה שלא נמצאו בה פנים מסומנת
   כמעובדת כדי שלא תיסרק שוב. כישלון בתמונה אחת אינו עוצר את התהליך.

תמונה חדשה שמועלית או מאושרת נכנסת אוטומטית לאינדוקס ברקע; כישלון בזיהוי
הפנים אינו מעכב ואינו מכשיל את ההעלאה, והתמונה תיאסף בריצת האינדוקס הבאה.

### החלפת גרסת מודל

`FACE_MODEL_VERSION` מוגדר גם ב־`cloudflare-worker.js` וגם ב־`face-search.js`
וחייב להיות זהה בשניהם. שינוי הערך מחזיר את כל התמונות לתור האינדוקס באופן
אוטומטי, והחיפוש משתמש רק בטביעות של הגרסה הנוכחית. כפתור **איפוס ואינדוקס
מחדש** (מנהל־על) מוחק את כל הטביעות השמורות לפני סריקה נקייה.

### נקודות הקצה

| נתיב | הרשאה | תפקיד |
|---|---|---|
| `POST /face/search` | משתמש מחובר ומאושר | השוואת טביעה מול הגלריה; מחזיר `imageId`, `distance`, `confidence`, `strength` |
| `POST /face/index` | מנהל או תהליך אינדוקס | שמירה ועדכון של טביעות לתמונה (כמה פרצופים לתמונה) |
| `POST /face/index/pending` | מנהל או תהליך אינדוקס | אילו תמונות עדיין ממתינות לאינדוקס |
| `GET /face/index/summary` | משתמש מחובר ומאושר | מוני התקדמות בלבד |
| `POST /face/index/reset` | מנהל־על | מחיקת טביעות לפני אינדוקס מחדש |

כל נקודות הקצה מוגבלות בקצב, מספר התוצאות בחיפוש מוגבל, וכל טביעה נבדקת
לפני שמירה: בדיוק 128 מספרים סופיים בטווח סביר. מחיקת תמונה — ברשומה או
בקובץ שב־R2 — מוחקת גם את כל טביעות הפנים שלה.

## הודעת הפופ-אפ

מנהל־על מעלה תמונה אחת שמוצגת למבקרים בכניסה לאתר, ובוחר לאן הלחיצה עליה
מפנה. מתחת לתמונה מוצג כפתור פעולה שנושא את שם היעד, כדי שהפנייה תהיה גלויה
ולא תסתמך על ניחוש שהתמונה לחיצה. הפופ-אפ נסגר לפני שהיעד נפתח, משום שהוא
יושב מעל שאר החלונות.

| יעד הפנייה | מה נפתח |
|---|---|
| ללא פנייה | רק התמונה, בלי כפתור פעולה |
| תיקייה ספציפית | הגלריה עם התיקייה שנבחרה |
| עדכונים אחרונים | כל התמונות, ממוינות מהחדש לישן |
| כלי באתר | אחד משישה כלים: חיפוש פנים ב־AI, חיפוש AI לפי תיאור, העלאת תמונות וסרטונים, המועדפים שלי, צ׳אט עם מנהל הגלריה, הפרופיל וההתראות |

כל כלי נפתח דרך אותה נקודת כניסה שהמשתמש לוחץ עליה באתר, ולכן בדיקות
ההרשאה נשארות במקום אחד: מי שאינו מאושר ולוחץ על פנייה לחיפוש פנים מקבל את
אותה הודעה שהיה מקבל מהכפתור הרגיל. רשימת הכלים מוגדרת ב־`POPUP_FEATURE_TARGETS`
שב־`admin.js`; הוספת כלי היא הוספת רשומה אחת שם, והיא מופיעה מאליה בבחירה
שבלוח הניהול. הודעות שנשמרו לפני התוספת ממשיכות לעבוד כפי שהן.

## חיבור Cloudflare D1

1. ב־Cloudflare פתח **Storage & databases → D1 SQL database** וצור מסד בשם `simchas-gallery-db`.
2. פתח את המסד, עבור ל־**Console**, הדבק את תוכן `cloudflare-d1-schema.sql` והפעל אותו.
3. פתח את ה־Worker הקיים `simchas-gallery-api`.
4. תחת **Settings → Bindings** הוסף **D1 database binding** בשם המדויק `GALLERY_DB` ובחר את המסד שיצרת.
5. החלף את קוד ה־Worker בתוכן `cloudflare-worker.js` ופרוס.

יש להשאיר את חיבור R2 הקיים בשם `GALLERY_BUCKET`.

## משתנים וסודות ב־Worker

| שם | סוג | שימוש |
|---|---|---|
| `GOOGLE_CLIENT_ID` | Text | מזהה לקוח Google; אם חסר, קיימת ברירת המחדל של האתר |
| `OPENAI_API_KEY` | Secret | חיפוש תמונות לפי תיאור |
| `RESEND_API_KEY` | Secret | שליחת דוא״ל מתוך הניהול |
| `EMAIL_FROM` | Text | כתובת שולח מאומתת |
| `GOOGLE_DRIVE_CLIENT_ID` | Text | חיבור Google Drive קבוע |
| `GOOGLE_DRIVE_CLIENT_SECRET` | Secret | סוד OAuth של Google Drive |
| `GOOGLE_DRIVE_REDIRECT_URI` | Text | כתובת החזרה של ה־Worker |
| `DRIVE_SITE_URL` | Text | כתובת אתר הגלריה |
| `FACE_INDEX_TOKEN` | Secret | רשות (אופציונלי): אסימון לתהליך אינדוקס פנים חיצוני, נשלח בכותרת `X-Face-Index-Token` |
| `SESSION_SIGNING_SECRET` | Secret | רשות (אופציונלי): מפתח החתימה של אסימוני ההתחברות. אם אינו מוגדר, ה־Worker מייצר מפתח אקראי ושומר אותו ב־D1 |

המשתנים הישנים `FIREBASE_API_KEY`, `FIREBASE_PROJECT_ID` ו־`FIREBASE_APP_ID` אינם בשימוש וניתן למחוק אותם רק לאחר שהמעבר נבדק.

## שמירת ההתחברות

אסימון של Google תקף כשעה בלבד, ולכן הוא משמש רק לכניסה הראשונה. מיד אחריה
ה־Worker מנפיק אסימון התחברות משלו, חתום ב־HMAC ותקף שלושים יום, והדפדפן שומר
אותו ב־`localStorage`. התוצאה: מי שהתחבר פעם אחת נשאר מחובר באותו דפדפן — גם
אחרי סגירת הלשונית, גם בלשוניות נוספות — עד שהוא מתנתק בעצמו. האסימון מתחדש
ברקע כשבוע לפני שתוקפו פג.

ההרשאות נקראות מהמסד בכל בקשה, ולכן חסימה או שינוי דרגה של משתמש נכנסים לתוקף
מיד, גם אם האסימון שבידיו עדיין תקף.

שינוי הערך של `SESSION_SIGNING_SECRET`, או מחיקת הטבלה `auth_secrets`, מבטל את
כל אסימוני ההתחברות הקיימים ומחייב את כל המשתמשים להתחבר מחדש.

## פריסה

האתר מתפרסם אוטומטית מ־GitHub Pages לאחר עדכון ענף `main`. גם ה־Worker נפרס
אוטומטית באמצעות `.github/workflows/deploy-worker.yml` בכל שינוי של
`cloudflare-worker.js` בענף `main`. לפני ההפעלה הראשונה יש להגדיר ב־GitHub,
תחת **Settings → Secrets and variables → Actions**, סוד אחד בלבד:

| סוד | ערך |
|---|---|
| `CLOUDFLARE_API_TOKEN` | אסימון Cloudflare בעל הרשאת Workers Scripts:Edit |

הפריסה קוראת את שמות כל ה־Bindings מהגרסה הפעילה ומורישה אותם לגרסה החדשה.
לפני העלאה היא מוודאת ש־`GALLERY_DB` ו־`GALLERY_BUCKET` קיימים, ולכן אינה
יוצרת מסד או דלי חדשים ואינה זקוקה למזהים שלהם ב־GitHub. לאחר הפריסה מתבצעת
בדיקת `/health` שמוודאת כי D1 ו־R2 מחוברים. אפשר גם להפעיל פריסה ידנית מתוך
**Actions → Deploy Cloudflare Worker → Run workflow**.

לפני מעבר סופי מומלץ להוריד גיבוי JSON מממשק הניהול הישן, ולאחר חיבור D1 לשחזר אותו דרך מסך הגיבוי באתר. קובצי המדיה עצמם נשארים ב־R2.

## אבטחה והרשאות

- Google ID Token נבדק בשרת וגם מול מזהה הלקוח הנכון.
- משתמש חדש נוצר תמיד בדרגת `viewer` ובמצב `pending`; הוא אינו יכול לאשר את עצמו.
- מנהל־על בלבד יכול לשנות דרגות, לחסום משתמשים ולנהל את סל המחזור.
- סודות נשמרים רק במשתני Cloudflare ואינם נכנסים ל־GitHub.
- חיפוש פנים זמין רק למשתמש מחובר ומאושר; כתיבת טביעות פנים זמינה למנהל או
  לתהליך אינדוקס מורשה בלבד.
